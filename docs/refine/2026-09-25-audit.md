# Codebase Audit — gdt-plugin-assets (follow-up)

**Date:** 2026-09-25
**Scope:** Full project, with focus on code added since the 2026-03-23
audit (`docs/refine/2026-03-23-audit.md`) — `internal/rename/`,
`internal/refs/repair.go`, `internal/policy/profile.go`,
`internal/analyzer/image.go`'s metadata/power-of-two logic
**Source files analyzed:** ~30 non-test `.go` files

## Prior audit re-verification

All 11 findings from the 2026-03-23 audit were checked against current
source before running anything new, rather than assumed still valid
after 6 months of unaudited changes:

- **Resolved** (confirmed fixed, not re-flagged): `RepairRef` dead
  export removed; `Options.PathGlob`/`Options.Fast` dead fields
  removed; oversize-check duplication across image/audio/model
  analyzers consolidated into a shared `checkOversize()` helper;
  format-set-construction duplication consolidated into
  `buildFormatSet()`; default-policy-defined-twice resolved —
  `cmd/init.go` now generates the TOML from `policy.MarshalDefault()`
  instead of a separate hand-written template; scan boilerplate across
  6 command handlers consolidated into a shared `scanAssets()` helper;
  doctor command now explicitly requires `check` as its first arg;
  `dedupe.FindExact` now early-returns when no hashes are present.
- **Reassessed as not currently valid** (was rated Critical):
  `refs.FindBroken`'s "re-walks when the scanner has already walked"
  framing — `FindBrokenInFiles(root, paths)` now exists as an
  alternative, but no current call site (`hookBeforeRun`, `cmdRefs`)
  does a second walk within one invocation; each does exactly one
  walk already, the minimum necessary. No evidence of the originally
  claimed redundant work in any code path that actually exists today.
- **Still open, unchanged**: `internal/cmd/pkgcmd.go` bypasses the
  analyzer interface (info-severity, architectural consistency only —
  declined below, same reasoning as March).

## New findings

### Fixed

- `internal/refs/repair.go:58` (`PlanRepairFromRenames`) — silently
  discarded any per-file error from `PlanRepair` (`continue` with no
  logging). An unreadable `.tscn`/`.tres` file meant the repair plan
  silently contained fewer ops than it should, with no indication —
  a user running `--apply` could end up with an inconsistent project
  and no idea some references were never checked. Fixed: the function
  now returns a `map[string]error` of skipped files alongside the
  plan; the one call site (`cmd/refs.go`) prints a `WARN` line per
  skipped file.
- `internal/scanner/scanner.go:34` (`Scan`'s `filepath.Walk` callback)
  — same class of bug: any per-path error (permission denied, broken
  symlink) was silently skipped with `return nil`, so a scan could
  under-report the asset inventory with zero indication. Fixed: now
  prints a `WARN` line per skipped path before continuing. Chose a
  direct stderr warning over a signature change (unlike `repair.go`)
  because `Scan` has 3 direct callers versus 1, and the codebase
  already uses this exact `WARN`-line convention extensively.
- Six diagnostics missing `Category` (`internal/analyzer/image.go`
  `image.pot`, `audio.go` `audio.format`, `model.go` `model.fbx`,
  `name.go` `naming.no_spaces`/`naming.case`, `structure.go`
  `structure.folder`) — `Category` is part of the documented JSON
  output schema (`CHANGELOG` v0.2.0: "Diagnostic category field for
  grouping (naming, structure, metadata, optimization)"), and every
  other diagnostic already sets it. These six were the only gaps.
  Assigned the category matching each rule's own taxonomy (checked
  against the CHANGELOG's stated four categories and each analyzer's
  existing sibling diagnostics, not guessed).
- `internal/rename/rename.go:28` (`ToSnakeCase`) — collapsed
  consecutive underscores via a `strings.Contains`/`ReplaceAll` loop
  instead of a single regex pass, despite the same file already using
  two compiled regexes for the adjacent transforms. Replaced with a
  third (`multiUnderscoreRe = regexp.MustCompile("_+")`) — same
  output (verified against the existing `TestToSnakeCase` table),
  consistent with the file's own style, technically also removes an
  unbounded-iteration shape for pathological input.

### Declined (with reasoning, not silently dropped)

- `internal/analyzer/image.go:64` (`isUIPath`) hardcodes `/ui/`,
  `/gui/`, `/hud/` rather than reading from policy — real portability
  gap, but no evidenced user pain with a non-standard UI folder name,
  and fixing it means designing a new policy field. YAGNI.
- `isUIPath`'s per-call string-operation cost — info-tier, no
  measurement showing this matters at any real asset count.
- `internal/cmd/pkgcmd.go` bypassing the analyzer interface — same
  call as the March audit: architectural consistency preference, no
  concrete pain, `Analyzer` interface would need to accommodate
  package-validation's different inputs for no current benefit.
- `internal/cmd/scan.go:18`'s `--profile` flag being an inert
  placeholder — already honestly labeled "(reserved for future use)"
  in its own `--help` text; `cmdScan` doesn't load a policy at all, so
  there's nothing to wire it to yet. Removing it now just to remove it
  isn't warranted; implementing it prematurely isn't either.
- `internal/refs/repair.go:81` (`ApplyRepair`'s `strings.ReplaceAll`)
  — audited claim was that renaming `res://ui/button` could
  accidentally also match `res://ui/buttons`. Verified false: the
  match/replace pattern includes the closing quote
  (`path="res://ui/button"`), which `res://ui/buttons` cannot satisfy
  as a substring. No fix needed; the audit's specific scenario doesn't
  occur.
